# 命令行与智能体

每一个安装好的 GenOffice 版本内部都随包附带了一个名为 `genoffice` 的命令行工具（CLI）。它并不是一套阉割版的外部脚本，而是直接驱动着与桌面端窗口完全相同的底层核心引擎——同一套文档解析器、同一套字节级保守写入器、同一套所见即所得排版渲染器。因此，用 `genoffice` 命令在终端里改出来或转换出来的文件，与你在图形界面窗口里亲手点保存生成的文件分毫不差；在桌面端 AI 面板里能通过的排版与格式校验，在命令行里同样严格执行。

```sh
genoffice --help          # every command
genoffice guide slides    # the op reference, for writing your own
```

在终端里敲下 `genoffice --help`，整个命令行工具的能力版图就会在一屏之内清晰展开——顶部是当前版本号，中间按顺序列出每一条子命令及其一句话职责说明，底部则是全局通用参数与标准退出状态码说明：

## 如何把 `genoffice` 命令装进系统终端 PATH

在 macOS 和 Windows 上，`genoffice` 可执行文件默认打包在应用程序安装目录内部（Linux 的 `.deb` 与 `.rpm` 包在安装时已自动注册）。如果你想在任何终端窗口里直接敲 `genoffice` 调用它，只需要运行一次自带的 `genoffice install-cli` 命令：在 macOS 上，它会把应用包内的二进制文件软链接到你 `PATH` 环境变量下的目录中——如果 `/usr/local/bin` 存在且不属于 Homebrew 管理的目录，会优先链接到那里（它绝不会去篡改或污染 Homebrew 自己管辖的目录），否则会自动链接到你当前用户的个人 `bin` 目录；在 Windows 上，它则会自动把命令所在路径注册进你当前用户的 `PATH` 环境变量里。

## 核心子命令一览

| 命令              | 作用                                                                                                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`            | 在 GenOffice 桌面窗口中打开指定文档；如果当前桌面应用还没启动，会自动先拉起应用再打开标签页。                                                                                                                          |
| `selection`       | 当桌面应用正在运行时，实时读取用户此时此刻在当前打开文档里用鼠标选中的内容——相当于给外部编程助手装上了看懂“把这段改一下”“算一下这几行”的指路指针，按编辑器类型返回段落范围、单元格坐标、幻灯片元素或页码。             |
| `convert`         | 调用应用自研的本地转换引擎，在 `.docx`、`.xlsx`、`.pptx`、`.pdf`、`.md`、`.html` 等格式之间直接离线互转。                                                                                                              |
| `create`          | 根据传入的结构化 JSON、CSV 或 Markdown 内容，直接从零构建出一份全新的标准办公文档。                                                                                                                                    |
| `render`          | 调用应用的真实排版渲染器，把文档的每一页或每一张幻灯片渲染输出为一张高清 `.png` 图片，方便人工或视觉模型检查版面。                                                                                                     |
| `pdf`             | 直接在命令行进程内逐页提取并读取 PDF 文档的文字层内容，全程无需启动图形界面主进程。                                                                                                                                    |
| `info`            | 快速输出一份陌生文档的元数据、页数、工作表清单与大纲结构摘要。                                                                                                                                                         |
| `search`          | 借用你在 GenOffice 设置里已经配好的联网搜索服务商，直接在终端里执行网页或图片检索。                                                                                                                                    |
| `image` / `media` | 借用应用内配置的生图与多模态模型生成配图，或者对本地图片、视频、音频文件做内容描述与视觉问答。                                                                                                                         |
| `merge`           | 批量读取数据并填充 `.docx`、`.pptx` 或 `.xlsx` 模板文件里的 `{{key}}` 占位符，适合批量出合同或通知书。                                                                                                                 |
| `capabilities`    | 检查并报告当前这台电脑上的 GenOffice 已经配置妥当并可立即调用哪些云端模型与多模态能力。                                                                                                                                |
| `guide`           | 打印内置的完整操作指令参考手册与排版设计指南——这份文档由底层执行器用来校验参数的同一份代码定义动态生成，因此永远不会出现“文档写着支持、执行时却报错”的脱节；加上 `--json` 参数还会一并输出每个操作的严格 JSON Schema。 |
| `install-cli`     | 将 `genoffice` 命令一键注册到当前系统的终端 `PATH` 环境变量中。                                                                                                                                                        |
| `skill`           | 自动扫描本机已安装的各类 AI 编程代理（如 Claude Code、Cursor、Codex、OpenCode 等），并为其一键安装或更新 GenOffice 专用技能包。                                                                                        |
| `mcp`             | 将上述每一条文档读写与转换命令封装为标准的 Model Context Protocol（MCP）工具对外提供服务，详细接入方式见**连接编程助手**一章。                                                                                         |

## 结构化读取与精准编辑：`docs`、`sheet`、`slides`

当你需要读取或修改现有文档时，`genoffice docs`、`genoffice sheet` 和 `genoffice slides` 这三个核心领域命令后面都会紧跟一个具体的动作子命令——三者都支持 `read`（读取结构）、`apply`（执行修改）和 `check`（校验完整性），而 `slides` 还额外提供专为演示文稿设计的 `audit`（版面审美与溢出审计）、`render`（逐页渲染截图）与 `replace`（批量文本替换）——所有修改最终都通过与桌面端窗口完全相同的原子写入管线落盘。这三个领域共享同一套简洁清晰的术语：每一次具体的原子修改动作称为一个 **op**（操作），而把一连串 op 按先后顺序打包在一起的 JSON 清单则称为一份 **spec**（修改规范）。

```sh
genoffice sheet read report.xlsx
genoffice slides apply deck.pptx --ops ops.json --dry-run
genoffice docs apply brief.docx --ops ops.json
```

在真正往磁盘文件上动刀之前，你随时可以在 `apply` 命令后面加上 `--dry-run`（演练模式）参数：它会完整跑一遍参数校验与模拟执行，详细汇报这批 `ops.json` 将会修改哪些段落、哪些单元格或哪几张幻灯片，但**绝不会往磁盘写入哪怕一个字节**——这是智能体或脚本在落盘前自查语法错误最稳妥的办法。事实上，GenOffice 桌面端右侧的 AI 助手面板在帮你改文档时，底层跑的正是这一模一样的 op 集合，因此凡是你能在窗口里让 AI 办到的事情，全都可以分毫不差地写成自动化脚本。

## 通过 Model Context Protocol（MCP）赋能外部智能体

运行 `genoffice mcp` 即可将上面所有的命令行能力作为标准 MCP 工具暴露给外部 AI 客户端；而运行 `genoffice mcp install <agent|all>` 则能自动把这套 MCP 服务写进你电脑上各个编程助手的配置文件里。关于图形界面与命令行下的完整对接步骤，请紧接着阅读下一章**连接编程助手**。

## 命令行工具的职责边界

`genoffice` 命令行工具的设计哲学非常纯粹：它只专注于在无界面或脚本环境下高速、精准地读写和转换文档文件，它本身并不是那个常驻桌面的图形界面应用——因此命令行进程自己不会弹出主窗口，也不负责处理应用内的版本更新弹窗。凡是那些必须依赖交互式图形窗口才能完成的体验（例如打开右侧 AI 聊天面板与助手多轮对话，或是对正在编辑的窗口做实时交互），都需要等你用 `genoffice open` 把文件在桌面窗口里打开后进行；不过，如果你只是想在没有窗口的服务器或终端里拿到渲染后的页面像素来做质量检查，`genoffice render` 完全可以在后台无头渲染出高清 PNG，而 `genoffice slides audit` 也能直接在终端里独立完成对整份 PPT 版面布局的自动化体检。
