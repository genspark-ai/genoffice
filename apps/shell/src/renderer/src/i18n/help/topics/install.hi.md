# GenOffice इंस्टॉल करना

हर बिल्ड [Releases पेज](https://github.com/genspark-ai/genoffice/releases/latest) पर प्रकाशित होता है। सभी `main` से बनी होती हैं; और macOS तथा Windows के इंस्टॉलर हस्ताक्षरित होते हैं।

## अपने मशीन के लिए फ़ाइल चुनें

| प्लेटफ़ॉर्म                          | आवश्यकताएँ                                            | फ़ाइल                 |
| ------------------------------------ | ----------------------------------------------------- | --------------------- |
| **macOS** — Apple Silicon            | macOS 11+                                             | `.dmg` (arm64)        |
| **macOS** — Intel                    | macOS 11+                                             | `.dmg` (x64)          |
| **Windows** — अधिकतर PC              | Windows 10+, Intel/AMD                                | `-x64.exe` इंस्टॉलर   |
| **Windows** पर Arm                   | Arm पर Windows 11 (Snapdragon X और समान)              | `-arm64.exe` इंस्टॉलर |
| **Linux** — Debian / Ubuntu          | x86_64, glibc 2.34+ (Ubuntu 22.04 या नया)             | `.deb`                |
| **Linux** — Fedora / RHEL / openSUSE | x86_64, glibc 2.34+ (Fedora 35+, RHEL 9+, Leap 15.6+) | `.rpm`                |
| **Linux** — कोई भी अन्य              | x86_64, glibc 2.34+, FUSE 2                           | `.AppImage`           |

पुराने संस्करण Releases पेज पर ही बने रहते हैं।

## macOS पर

`.dmg` खोलें और **GenOffice** को Applications में खींचें। Intel बिल्ड में पहली बार चलाने पर यह खोलने की पुष्टि माँगता है: Applications में ऐप पर राइट-क्लिक करके ▸ खोलें चुनें। यह बिना हस्ताक्षर वाली डिस्क इमेज के सामने Gatekeeper है, क्षतिग्रस्त डाउनलोड नहीं।

## Windows पर

`.exe` इंस्टॉलर चलाएँ। यह GenOffice को Start मेन्यू में रखता है और `.docx`, `.xlsx`, `.pptx`, `.pdf` तथा इन्हीं जैसे प्रकार पंजीकृत कर देता है, ताकि किसी फ़ाइल पर डबल-क्लिक उसे खोल दे।

## Linux पर

**Debian / Ubuntu**

```sh
sudo apt install ./genoffice_<version>_amd64.deb
```

**Fedora / RHEL / openSUSE**

```sh
sudo dnf install ./genoffice-<version>.x86_64.rpm     # Fedora / RHEL family
sudo zypper install ./genoffice-<version>.x86_64.rpm  # openSUSE
```

**AppImage** — बिना किसी इंस्टॉल चरण के, जहाँ है वहीं चलता है:

```sh
chmod +x GenOffice-<version>.AppImage
./GenOffice-<version>.AppImage
```

इसे FUSE 2 रनटाइम चाहिए। यदि आप इसे इंस्टॉल नहीं करना चाहते, तो `--appimage-extract-and-run` के साथ चलाएँ, और सैंडबॉक्स निकाली गई निर्देशिका से ही काम करेगी।

## जिस बिल्ड को आप चला रहे हैं

**सेटिंग्स ▸ जानकारी** वही जगह है जहाँ ऐप बताता है कि आपके पास कौन-सा बिल्ड है, वह कौन-सा चैनल अपनाता है और प्रोजेक्ट कहाँ रहता है। जब उसी चैनल पर नया बिल्ड प्रकाशित होता है, वही पैनल अपडेट की पेशकश कर देता है; Flatpak, Nix या Docker इंस्टॉल में ऐसा नहीं होता, क्योंकि वहाँ की इंस्टॉल को वही औज़ार बदल देता है जिसने उसे वहाँ रखा था।

## और तीन रास्ते

तीनों ऐप को दोबारा बनाने के बजाय प्रकाशित आर्टिफ़ैक्ट को लपेटते हैं, इसलिए वे आधिकारिक बाइनरी के अनुसार चलते हैं।

- **Flatpak** — `.deb` को Flatpak के `extra-data` तंत्र से इंस्टॉल करता है और Zypak के अंतर्गत चलाता है, जो Electron के अपने सैंडबॉक्स को अनुकूलित करता है। `/app` वृक्ष पढ़ने-योग्य होता है, इसलिए अपडेट ऐप के भीतर की अपडेट संवाद की बजाय Flatpak से जाते हैं।
- **Nix** — एक पैकेज एक्सप्रेशन जिसे आप एक चेकआउट से `nix-build packaging/nix` के साथ बनाते हैं; देखें `packaging/nix`।
- **Docker** — एक बिना इंटरफ़ेस वाला बैच-रूपांतरण इमेज (`packaging/docker`)। यह ऐप के अपने निर्यात पाइपलाइन से Office, Markdown और HTML दस्तावेज़ों के पूरे पेड़ को PDF में बदलता है, इसलिए निर्गत वही होता है जो File ▸ एक्सपोर्ट देता। यह एक CLI उपकरण है, सर्वर नहीं।

## कमांड लाइन भी साथ आती है

हर इंस्टॉल में `genoffice` कमांड रहती है जो उसी इंजनों से बात करती है जिन्हें विंडो इस्तेमाल करती है, इसलिए दोनों किसी फ़ाइल पर कभी असहमत नहीं होतीं। macOS और Windows पर यह ऐप बंडल के भीतर होती है; और `genoffice install-cli` इसे आपके `PATH` में रख देती है। यह क्या कर सकती है, इसके लिए **कमांड लाइन और एजेंट** देखें।
