# سطر الأوامر والوكلاء

كل تثبيت يشحن أمر `genoffice` يقود المحركات نفسها التي تستخدمها النافذة — المحلّلات نفسها، والكاتب نفسه، والمحرّك نفسه. الملف الذي يحفظه التطبيق والملف الذي يكتبه الأمر هما الملف نفسه، والفحص الذي يجتازه لوحة الذكاء الاصطناعي في التطبيق يجتازه الأمر أيضًا.

```sh
genoffice --help          # every command
genoffice guide slides    # the op reference, for writing your own
```

## الحصول على الأمر

يشحنه macOS وWindows داخل حزمة التطبيق. لاستخدامه باسمه، شغّل `genoffice install-cli` مرة واحدة: فهو ينشئ ارتباطًا رمزيًا للملف التنفيذي المضمّن في `/usr/local/bin`، أو في `PATH` الخاص بمستخدمك على Windows.

## الأوامر التي تستحق المعرفة

| الأمر | وظيفته |
| --- | --- |
| `open` | فتح مستند داخل التطبيق؛ ويشغّل التطبيق إن لم يكن يعمل. |
| `convert` | التحويل بين الصيغ باستخدام محركات التطبيق نفسها. |
| `create` | إنشاء مستند من محتوى منظَّم. |
| `render` | صورة PNG لكل صفحة، بالتخطيط الذي ينفّذه المحرّك. |
| `pdf` | قراءة الطبقة النصية لملف PDF صفحةً بصفحة، دون أي عملية تطبيق. |
| `info` | البيانات الوصفية وملخّص لبنية المستند. |
| `search` | بحث في الويب أو الصور عبر المزوّد المهيّأ في التطبيق. |
| `image` / `media` | توليد صورة، أو وصف صورة أو ملف فيديو أو صوتي والسؤال عنه. |
| `merge` | ملء العناصر النائبة `{{key}}` في قالب `.docx` أو `.pptx` أو `.xlsx`. |
| `capabilities` | الإبلاغ عن ميزات السحابة المهيّأة على هذا الجهاز. |
| `guide` | مرجع العمليات وأدلة التصميم، مولَّد من التعريفات نفسها التي يتحقق منها المنفّذ — لذا لا يمكن أن ينحرف عمّا يقبله `apply`. ويعيد `--json` المرجع مع مخطط كل عملية. |
| `install-cli` | وضع `genoffice` في `PATH`. |
| `skill` | عرض وكلاء البرمجة الموجودين على هذا الجهاز وتثبيت مهارة GenOffice فيها أو تحديثها. |
| `mcp` | تقديم كل أمر كأداة ضمن Model Context Protocol. انظر **ربط وكيل برمجي**. |

## التحرير: مستندات وجداول وعروض

`genoffice docs` و`genoffice sheet` و`genoffice slides` تقرأ وتحرّر عبر مسار الكتابة نفسه الذي يستخدمه التطبيق، وهي تتشارك مفردات واحدة: **العملية** (op) هي تعديل واحد، و**المواصفة** (spec) قائمة عمليات تُطبَّق بالترتيب.

```sh
genoffice sheet read report.xlsx
genoffice slides apply deck.pptx --ops ops.json --dry-run
genoffice docs apply brief.docx --ops ops.json
```

يعرض `--dry-run` ما ستفعله دفعة ولا يكتب شيئًا، وهذه أرخص طريقة للتحقق من مواصفة قبل تطبيقها. ولوحة الذكاء الاصطناعي في التطبيق تعمل على هذه العمليات بالضبط، فأي شيء تطلبه منها يمكنك برمجته.

## Model Context Protocol

يقدّم `genoffice mcp` كل أمر كأداة MCP، ويسجّل `genoffice mcp install <agent|all>` في إعداد وكيل البرمجة نفسه. انظر **ربط وكيل برمجي** لتلك الجهة.

## ما لا يفعله الأمر

هو يقرأ الملف ويكتبه. لكنه ليس التطبيق: لا توجد نافذة، ولا ينطبق حوار التحديث داخل التطبيق. وأي شيء يحتاج إلى النافذة — لوحة الذكاء الاصطناعي، أو مراجعة الجودة QC لشريحة مُعرضة — عليه أن ينتظر حتى تفتح الملف. ويمنحك `genoffice render` البكسلات دون ذلك، وتُدقّق `genoffice slides` في تخطيط العرض بنفسها.
