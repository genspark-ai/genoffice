# שורת פקודה וסוכנים

כל התקנה כוללת פקודת `genoffice` שמנהלת את אותם מנועים שהחלון משתמש בהם — אותם מנתחים, אותו כותב, אותו מרונדר. קובץ שהאפליקציה שומרת וקובץ שהפקודה כותבת הם אותו קובץ, ובדיקה שחלונית ה-AI של האפליקציה עוברת היא בדיקה שגם הפקודה עוברת.

```sh
genoffice --help          # every command
genoffice guide slides    # the op reference, for writing your own
```

## קבלת הפקודה

‏macOS ו-Windows מגיעים עמה בתוך חבילת האפליקציה. כדי להשתמש בה לפי השם, הריצו פעם אחת `genoffice install-cli`: היא יוצרת קישור סמבולי לקובץ ההפעלה המצורף אל `/usr/local/bin`, או אל `PATH` של המשתמש שלכם ב-Windows.

## הפקודות שכדאי להכיר

| פקודה | מה היא עושה |
| --- | --- |
| `open` | פותחת מסמך באפליקציה; מפעילה את האפליקציה אם היא לא רצה. |
| `convert` | ממירה בין פורמטים באמצעות המנועים של האפליקציה עצמה. |
| `create` | יוצרת מסמך מתוכן מובנה. |
| `render` | PNG אחד לכל עמוד, לפי הפריסה של המרונדר. |
| `pdf` | קוראת את שכבת הטקסט של PDF עמוד אחר עמוד, בלי תהליך של האפליקציה. |
| `info` | מטא-נתונים ותקציר מבנה של מסמך. |
| `search` | חיפוש ברשת או בתמונות דרך הספק המוגדר באפליקציה. |
| `image` / `media` | יוצרת תמונה, או מתארת קובץ תמונה, וידאו או שמע ועונה עליו שאלות. |
| `merge` | ממלאת מציידי מקום `{{key}}` בתבנית `.docx`, `.pptx` או `.xlsx`. |
| `capabilities` | מדווחת אילו יכולות ענן מוגדרות במחשב הזה. |
| `guide` | מפניית הפעולות ומדריכי העיצוב, נוצרות מאותם הגדרות שמולן המבצע מאמת — ולכן היא לא יכולה לסטות ממה ש-`apply` מקבל. `--json` מחזיר אותה עם הסכמה של כל פעולה. |
| `install-cli` | מציבה את `genoffice` ב-`PATH`. |
| `skill` | מפרטת את סוכני התכנון שנמצאו במחשב הזה ומתקינה בהם או מעדכנת את המיומנות של GenOffice. |
| `mcp` | מגישה כל פקודה ככלי ב- Model Context Protocol. ראו **חיבור סוכן תכנון**. |

## עריכה: מסמכים, גיליונות, מצגות

‏`genoffice docs`, ‏`genoffice sheet` ו-`genoffice slides` קוראות ועורכות דרך אותו נתיב כתיבה שהאפליקציה עצמה משתמשת בו, והן חולקות מילון אחד: **פעולה** (op) היא עריכה בודדת, ו**מפרט** (spec) הוא רשימת פעולות המיושמות לפי הסדר.

```sh
genoffice sheet read report.xlsx
genoffice slides apply deck.pptx --ops ops.json --dry-run
genoffice docs apply brief.docx --ops ops.json
```

‏`--dry-run` מדווח מה אצווה הייתה עושה ולא כותב דבר, וזו הדרך הזולה לבדוק מפרט לפני שהוא נופל. חלונית ה-AI של האפליקציה רצה בדיוק על אותן פעולות, ולכן כל מה שאתם יכולים לבקש ממנה אפשר גם לתסריט.

## Model Context Protocol

‏`genoffice mcp` מגישה כל פקודה ככלי MCP, ו-`genoffice mcp install <agent|all>` רושמת אותה בהגדרות של סוכן התכנון עצמו. ראו **חיבור סוכן תכנון** לצד הזה.

## מה שהפקודה אינה עושה

היא קוראת את הקובץ וכותבת אותו. היא אינה האפליקציה: אין חלון, וחלונית העדכון שבאפליקציה אינה חלה. כל מה שדורש את החלון — חלונית ה-AI, ביקורת האיכות על שקופית מרונדרת — חייב לחכות שתפתחו את הקובץ. ‏`genoffice render` נותן לכם את הפיקסלים בלי זה, ו-`genoffice slides` בודקת את הפריסה של מצגת בעצמה.
