# 命令列與智慧代理

每一個安裝好的 GenOffice 版本內部都隨包附帶了一個名為 `genoffice` 的命令列工具（CLI）。它並不是一套閹割版的外部腳本，而是直接驅動著與桌面端視窗完全相同的底層核心引擎——同一套文件剖析器、同一套位元組級保守寫入器、同一套所見即所得排版渲染器。因此，用 `genoffice` 命令在終端機裡改出來或轉換出來的檔案，與你在圖形介面視窗裡親手點儲存生成的檔案分毫不差；在桌面端 AI 面板裡能通過的排版與格式校驗，在命令列裡同樣嚴格執行。

```sh
genoffice --help          # every command
genoffice guide slides    # the op reference, for writing your own
```

在終端機裡敲下 `genoffice --help`，整個命令列工具的能力版圖就會在一屏之內清晰展開——頂部是目前版本號，中間依序列出每一條子命令及其一句話職責說明，底部則是全域通用參數與標準結束狀態碼說明：

## 如何把 `genoffice` 命令裝進系統終端機 PATH

在 macOS 和 Windows 上，`genoffice` 可執行檔預設打包在應用程式安裝目錄內部（Linux 的 `.deb` 與 `.rpm` 套件在安裝時已自動註冊）。如果你想在任何終端機視窗裡直接敲 `genoffice` 呼叫它，只需要執行一次自帶的 `genoffice install-cli` 命令：在 macOS 上，它會把應用程式套件內的二進位檔案軟連結到你 `PATH` 環境變數下的目錄中——如果 `/usr/local/bin` 存在且不屬於 Homebrew 管理的目錄，會優先連結到那裡（它絕不會去篡改或污染 Homebrew 自己管轄的目錄），否則會自動連結到你目前使用者的個人 `bin` 目錄；在 Windows 上，它則會自動把命令所在路徑註冊進你目前使用者的 `PATH` 環境變數裡。

## 核心子命令一覽

| 命令              | 作用                                                                                                                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`            | 在 GenOffice 桌面視窗中開啟指定文件；如果目前桌面應用程式還沒啟動，會自動先拉起應用程式再開啟分頁。                                                                                                                        |
| `selection`       | 當桌面應用程式正在執行時，即時讀取使用者此時此刻在目前開啟文件裡用滑鼠選取的內容——相當於給外部程式設計助手裝上了看懂「把這段改一下」「算一下這幾列」的指路指標，依編輯器類型傳回段落範圍、儲存格座標、投影片元素或頁碼。   |
| `convert`         | 呼叫應用程式自研的本機轉換引擎，在 `.docx`、`.xlsx`、`.pptx`、`.pdf`、`.md`、`.html` 等格式之間直接離線互轉。                                                                                                              |
| `create`          | 根據傳入的結構化 JSON、CSV 或 Markdown 內容，直接從零建構出一份全新的標準辦公文件。                                                                                                                                        |
| `render`          | 呼叫應用程式的真實排版渲染器，把文件的每一頁或每一張投影片渲染輸出為一張高畫質 `.png` 圖片，方便人工或視覺模型檢查版面。                                                                                                   |
| `pdf`             | 直接在命令列程序內逐頁擷取並讀取 PDF 文件的文字層內容，全程無需啟動圖形介面主程序。                                                                                                                                        |
| `info`            | 快速輸出一份陌生文件的中繼資料、頁數、工作表清單與大綱結構摘要。                                                                                                                                                           |
| `search`          | 借用你在 GenOffice 設定裡已經配好的網路搜尋服務商，直接在終端機裡執行網頁或圖片檢索。                                                                                                                                      |
| `image` / `media` | 借用應用程式內設定的生圖與多模態模型生成配圖，或者對本機圖片、影片、音訊檔案做內容描述與視覺問答。                                                                                                                         |
| `merge`           | 批次讀取資料並填入 `.docx`、`.pptx` 或 `.xlsx` 範本檔案裡的 `{{key}}` 佔位符，適合批次出合約或通知書。                                                                                                                     |
| `capabilities`    | 檢查並回報目前這台電腦上的 GenOffice 已經設定妥當並可立即呼叫哪些雲端模型與多模態能力。                                                                                                                                    |
| `guide`           | 列印內建的完整操作指令參考手冊與排版設計指南——這份文件由底層執行器用來校驗參數的同一份程式碼定義動態生成，因此永遠不會出現「文件寫著支援、執行時卻報錯」的脫節；加上 `--json` 參數還會一併輸出每個操作的嚴格 JSON Schema。 |
| `install-cli`     | 將 `genoffice` 命令一鍵註冊到目前系統的終端機 `PATH` 環境變數中。                                                                                                                                                          |
| `skill`           | 自動掃描本機已安裝的各類 AI 程式設計代理（如 Claude Code、Cursor、Codex、OpenCode 等），並為其一鍵安裝或更新 GenOffice 專用技能包。                                                                                        |
| `mcp`             | 將上述每一條文件讀寫與轉換命令封裝為標準的 Model Context Protocol（MCP）工具對外提供服務，詳細接入方式見**連接程式設計助手**一章。                                                                                         |

## 結構化讀取與精準編輯：`docs`、`sheet`、`slides`

當你需要讀取或修改現有文件時，`genoffice docs`、`genoffice sheet` 和 `genoffice slides` 這三個核心領域命令後面都會緊跟一個具體的動作子命令——三者都支援 `read`（讀取結構）、`apply`（執行修改）和 `check`（校驗完整性），而 `slides` 還額外提供專為簡報設計的 `audit`（版面審美與溢出審計）、`render`（逐頁渲染截圖）與 `replace`（批次文字取代）——所有修改最終都透過與桌面端視窗完全相同的原子寫入管線寫入磁碟。這三個領域共用同一套簡潔清晰的術語：每一次具體的原子修改動作稱為一個 **op**（操作），而把一連串 op 依先後順序打包在一起的 JSON 清單則稱為一份 **spec**（修改規範）。

```sh
genoffice sheet read report.xlsx
genoffice slides apply deck.pptx --ops ops.json --dry-run
genoffice docs apply brief.docx --ops ops.json
```

在真正往磁碟檔案上動刀之前，你隨時可以在 `apply` 命令後面加上 `--dry-run`（演練模式）參數：它會完整跑一遍參數校驗與模擬執行，詳細回報這批 `ops.json` 將會修改哪些段落、哪些儲存格或哪幾張投影片，但**絕不會往磁碟寫入哪怕一個位元組**——這是智慧代理或腳本在寫入磁碟前自查語法錯誤最穩妥的辦法。事實上，GenOffice 桌面端右側的 AI 助理面板在幫你改文件時，底層跑的正是這一模一樣的 op 集合，因此凡是你能在視窗裡讓 AI 辦到的事情，全都可以分毫不差地寫成自動化腳本。

## 透過 Model Context Protocol（MCP）賦能外部智慧代理

執行 `genoffice mcp` 即可將上面所有的命令列能力作為標準 MCP 工具暴露給外部 AI 用戶端；而執行 `genoffice mcp install <agent|all>` 則能自動把這套 MCP 服務寫進你電腦上各個程式設計助手的設定檔裡。關於圖形介面與命令列下的完整對接步驟，請緊接著閱讀下一章**連接程式設計助手**。

## 命令列工具的職責邊界

`genoffice` 命令列工具的設計哲學非常純粹：它只專注於在無介面或腳本環境下高速、精準地讀寫和轉換文件檔案，它本身並不是那個常駐桌面的圖形介面應用程式——因此命令列程序自己不會彈出主視窗，也不負責處理應用程式內的版本更新彈窗。凡是那些必須依賴互動式圖形視窗才能完成的體驗（例如開啟右側 AI 聊天面板與助理多輪對話，或是對正在編輯的視窗做即時互動），都需要等你用 `genoffice open` 把檔案在桌面視窗裡開啟後進行；不過，如果你只是想在沒有視窗的伺服器或終端機裡拿到渲染後的頁面像素來做品質檢查，`genoffice render` 完全可以在背景無頭渲染出高畫質 PNG，而 `genoffice slides audit` 也能直接在終端機裡獨立完成對整份 PPT 版面配置的自動化體檢。
