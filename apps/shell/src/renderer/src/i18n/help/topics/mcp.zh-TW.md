# 連接程式設計助手

GenOffice 原生實作了標準的 **Model Context Protocol（MCP，模型上下文協定）**，同時提供了配套的 Agent 技能包（Skill）。這意味著你平時在電腦上使用的 Claude Code、Codex、Cursor、OpenCode、Windsurf 等 AI 程式設計助手，可以直接呼叫與 GenOffice 桌面端完全相同的底層引擎來為你讀取、建立、修改和渲染 Word、Excel、PPT 與 PDF 文件。外部智慧代理在操作文件時絕不是靠瞎猜二進位檔案格式，而是直接拿到了與 GenOffice 內部執行器同源的強型別操作定義（Typed Op Schema），每一步修改都經過嚴格校驗。

## 在桌面端設定面板中一鍵註冊

開啟 **設定 ▸ 整合**，就能看到專為連接外部程式設計助手設計的視覺化設定中心。整個面板上下分為「技能（Skill）」與「MCP 服務」兩大模組，你可以根據自己的使用習慣只啟用其中一種，也可以把兩種全都裝上。

**第一部分：安裝技能（Skills）。** 開啟面板時，GenOffice 會自動掃描你電腦上已經安裝好的主流程式設計代理——包括 Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、OpenCode 與 Windsurf——並把它們逐一列成清晰的管理列。每一列旁邊都配有**安裝**、**更新**與**解除安裝**按鈕，下方還提供**安裝到其他目錄…**、**下載 skill（zip 壓縮檔）**以及**複製路徑**三個靈活選項。如果你正在使用的自研智慧代理不在自動辨識清單裡，只需點擊「安裝到其他目錄…」並指向該智慧代理讀取 `SKILL.md` 的技能資料夾，或者把 zip 套件存下來交給你的助手自行解壓縮安裝即可。技能包與 MCP 服務完全可以和平共處：智慧代理會自動挑選它最順手的一條通道呼叫，而兩條通道底層執行的文件操作完全等價。

**第二部分：設定 MCP 服務。** 面板提供兩條接入路線供你任選：第一條是預設推薦的**由助手按需啟動（stdio 模式）**，你只需把介面上生成的標準設定片段一鍵複製或注入到你的 AI 用戶端裡，以後每當你在助手裡提到辦公文件時，助手自己就會在背景靜默拉起 `genoffice mcp` 程序幹活；第二條路線則是**本機 HTTP 服務**，由 GenOffice 桌面應用程式自己在背景常駐開啟一個本機連接埠供外部助手隨時連入。無論選哪一條路，設定好之後你都不需要再自己去終端機裡手敲任何命令。

**立刻試一試：** 安裝完成後，在你的程式設計助手裡新開一個對話視窗，直接像平時跟同事說話一樣交代文件任務即可，例如：

- “幫我把 `~/Downloads/report.md` 轉換成排版規範的 Word 文件”
- “根據目前目錄下的銷售數據，做一份 6 頁的投影片總結我們第三季度的業績亮點”
- “把 `budget.xlsx` 匯出成 PDF 檔案，並直接在 GenOffice 視窗裡幫我開啟”

## 從終端機命令列批次註冊（進階路徑）

如果你習慣在終端機裡用腳本管理開發環境，或者你的程式設計代理安裝在一些非標準的自訂目錄裡，也可以直接在命令列裡完成同樣的 MCP 註冊操作：

```sh
genoffice mcp install all
```

執行這條命令後，`genoffice` 會自動探測目前機器上已安裝的所有受支援程式設計代理，將 `genoffice` 的 stdio MCP 伺服器設定項目精準合併進每個代理各自的設定檔中，同時嚴密保護你設定檔裡原有的其他 MCP 伺服器項目不受影響。

```sh
genoffice mcp list             # where each agent stands
genoffice mcp install cursor    # just one
genoffice mcp uninstall cursor  # take it back out
```

如果你的某個程式設計代理安裝在非預設路徑下，可以在命令後加上 `--dir <自訂設定目錄>` 參數手動指定位置；如果某個代理裡之前已經配過舊版項目、想強制重新整理覆蓋它，加上 `--force` 參數即可。

在終端機執行 `genoffice mcp --help`，就能在一屏之內看清 MCP 伺服器支援的全部子命令與啟動參數——包括 `install`、`uninstall`、`list` 三種管理動作，切換為 HTTP 模式的網路參數，以及控制 Schema 體積的兩個開關：

![genoffice mcp --help 的真實輸出：install、uninstall 與 list 三種形式，以及 --http、--host、--token、--compact-schemas、--dir 和 --force 選項](img/mcp.png)

## 獨立啟動 HTTP 模式的 MCP 伺服器

當你的 AI 用戶端執行在容器、虛擬機器或區域網路內的另一台機器上、無法直接透過本機程序管道（stdio）拉起命令時，可以讓 `genoffice mcp` 以帶驗證的 HTTP 伺服器模式獨立執行：

```sh
genoffice mcp --http 8765 --token <secret>
```

你可以透過 `--host <監聽位址>` 指定它綁定的網路卡位址（預設僅綁定本機迴路位址以保安全），並在你的 AI 用戶端設定裡填上同一個 `--token` 存取權杖。

走 HTTP 遠端模式時，哪怕用戶端與 GenOffice 不在同一個檔案系統下，文件照樣能順暢流轉：用戶端可以透過 `PUT /files/<檔名>` 介面先把待處理的文件上傳過來，每一個 MCP 工具也都支援直接傳入 `http://` 或 `https://` 網址來代替本機磁碟路徑；處理完成後，生成的新文件會以可直接下載的 HTTP URL 傳回（如果生成的檔案體積足夠小，也會直接作為內嵌資源傳回）。至於結構化的編輯指令（op、spec）和 Markdown 文字，在 stdio 與 HTTP 兩種模式下都直接透過 JSON 請求主體行內傳遞。

## 外部智慧代理透過 MCP 能呼叫哪些核心工具

`genoffice` 命令列裡的每一項核心能力，在 MCP 協定下都會映射為一個結構化的標準工具，其中最常被智慧代理呼叫的有：

- **`docs`、`sheet`、`slides` 文件讀寫與編輯工具**：走與 GenOffice 桌面應用程式完全相同的底層寫入管線，以每次一個或多個 **op（原子操作）** 的粒度精準讀取和修改 `.docx`、`.xlsx` 與 `.pptx` 檔案；如果是從零建立一整套全新簡報，還會配合 `deck_start`、`deck_page` 與 `deck_build` 流水線工具保證版面品質。
- **`render` 頁面視覺渲染工具**：由應用程式內建的真實排版渲染器把文件或投影片逐頁渲染成高畫質 `.png` 圖片傳回給智慧代理，讓支援視覺的智慧代理能夠親眼「看」到自己排出來的版面有沒有文字重疊或溢出，而不是閉著眼睛瞎猜。
- **`pdf` 文字層讀取工具**：無需啟動沉重的桌面端視窗程序，直接在背景依頁高速擷取 PDF 文件裡的文字內容供智慧代理閱讀分析。
- **`info` 文件結構探針**：快速傳回一份陌生文件的頁數、章節大綱、工作表名稱與中繼資料摘要，通常是智慧代理接手一個新檔案時用來摸清底細的最佳第一通呼叫。
- **`search`、`image`、`media` 多模態與檢索工具**：直接共用你在 GenOffice 桌面端「設定」裡已經配好的網路搜尋、AI 生圖與音視訊理解服務商，這樣外部程式設計代理就不需要自己再去額外設定一套第三方 API 金鑰。
- **`merge` 範本批次填入工具**：讀取外部鍵值資料，一鍵取代並填入辦公文件範本裡的 `{{key}}` 佔位符。

## 精簡 Schema 模式：為上下文視窗吃緊的用戶端省空間

預設情況下，`apply` 和 `create` 等核心工具在向 MCP 用戶端宣告自己的 `ops`、`cells` 和 `data` 參數時，會輸出由 `genoffice guide <領域> --json` 生成的完整逐操作強型別 Schema。這種完整宣告對大模型寫出一次成功的合法參數非常有幫助，但 Schema 本身的 JSON 體積也相對較大。如果你使用的某個 MCP 用戶端對工具定義的長度有嚴格限制、或者上下文視窗預算比較吃緊，可以開啟**精簡 Schema 模式**，將複雜聯合型別收斂為輕量的基礎陣列宣告：

```sh
genoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 genoffice mcp
```

## 為什麼配了 MCP 還建議安裝「技能（Skill）」？

很多使用者會好奇：既然 MCP 已經把工具暴露給智慧代理了，為什麼面板裡還要提供「技能（Skill）」？原因在於，一個只拿到工具名卻沒讀過操作手冊與排版規範的智慧代理，在面對複雜的公文表格或 PPT 版面時依然容易去瞎猜參數。而 GenOffice 的**技能包（`SKILL.md`）**裡直接隨身攜帶了完整的操作指令參考手冊與高審美版面設計規範（與你在終端機執行 `genoffice guide` 看到的權威指南同源）——裝上技能後，智慧代理在下筆寫每一個 op 之前，都是真正熟讀過參數規格與排版禁忌的。你既可以在上面介紹的 **設定 ▸ 整合** 面板裡點一下按鈕安裝，也可以在終端機裡執行 `genoffice skill` 完成安裝。

## 與正在執行的 GenOffice 桌面視窗即時連動

GenOffice 的 MCP 伺服器絕不僅僅只能在背景悶頭改磁碟上的靜態檔案。只要你的 GenOffice 桌面應用程式正開著，外部程式設計智慧代理就可以直接與你眼前的視窗協同工作：

- **`open_in_genoffice`**：讓桌面視窗立刻在一個新分頁裡開啟指定檔案，並自動把該分頁切到最前台呈現給你看。
- **`open_documents`**：即時列出你目前在 GenOffice 視窗裡開啟的所有文件分頁清單（包含每個分頁的唯一 ID、編輯器類型、磁碟路徑，以及目前是否有尚未儲存的改動），並允許智慧代理直接讀取某個已開啟分頁裡的最新記憶體內容、觸發就地儲存，或者幫你將分頁安全關閉（預設會先儲存再關，除非你明確指示丟棄改動）。
- **直接往已開啟的分頁裡即時寫內容**：所有的文件編輯類工具都支援把上面查到的分頁 ID（或檔案路徑）直接作為 `document` 參數傳進去——這樣智慧代理做出的每一處文字潤飾、表格填數或投影片排版，都會**直接即時落在你眼前正開著的那個分頁畫布上**，並且主視窗會自動切過去讓你親眼看著修改發生。

當然，有兩塊純屬桌面互動的領地依然保持獨立：MCP 服務不會去操控你視窗右側的內建 AI 聊天面板，也不會觸發應用程式內的軟體版本更新對話框。

## 「本機 HTTP 服務」視覺化管控面板

如果你在 **設定 ▸ 整合** 下方選擇了**本機 HTTP 服務**模式，GenOffice 桌面端就會親自替你託管並守護這個 MCP 伺服器程序，無需外部助手去操心程序啟停。面板上提供了直觀的**啟用開關**、自訂**連接埠**輸入框、即時顯示**執行中／未執行**的狀態指示燈，以及**背景生成**開關（開啟後智慧代理生成文件時直接靜默寫到目標磁碟路徑，而不會每次都突然彈出一個新分頁打斷你），下方還附帶了一段可一鍵複製的**用戶端 JSON 設定範例**。當你點開**進階**摺疊區後，還會額外展示兩條標準連線端點位址（現代的 **Streamable HTTP** 位址與相容舊用戶端的 **SSE** 位址）、一個用於探測服務存活的**健康檢查**網址，以及一個**本機活動日誌**開關——開啟日誌後，伺服器收到的每一次 MCP 工具呼叫都會記錄到本機日誌檔案中，你可以隨時在面板上一鍵**開啟**、**重新整理**或**清除**日誌。出於安全隔離原則，該內建 HTTP 服務始終只綁定並監聽本機（`localhost`）。
