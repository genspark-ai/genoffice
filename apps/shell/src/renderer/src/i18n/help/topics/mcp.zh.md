# 连接编程助手

GenOffice 原生实现了标准的 **Model Context Protocol（MCP，模型上下文协议）**，同时提供了配套的 Agent 技能包（Skill）。这意味着你平时在电脑上使用的 Claude Code、Codex、Cursor、OpenCode、Windsurf 等 AI 编程助手，可以直接调用与 GenOffice 桌面端完全相同的底层引擎来为你读取、创建、修改和渲染 Word、Excel、PPT 与 PDF 文档。外部智能体在操作文档时绝不是靠瞎猜二进制文件格式，而是直接拿到了与 GenOffice 内部执行器同源的强类型操作定义（Typed Op Schema），每一步修改都经过严格校验。

## 在桌面端设置面板中一键注册

打开 **设置 ▸ 集成**，就能看到专为连接外部编程助手设计的可视化配置中心。整个面板上下分为「技能（Skill）」与「MCP 服务」两大模块，你可以根据自己的使用习惯只启用其中一种，也可以把两种全都装上。

**第一部分：安装技能（Skills）。** 打开面板时，GenOffice 会自动扫描你电脑上已经安装好的主流编程代理——包括 Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、OpenCode 与 Windsurf——并把它们逐一列成清晰的管理行。每一行旁边都配有**安装**、**更新**与**卸载**按钮，下方还提供**安装到其他目录…**、**下载 skill（zip 压缩包）**以及**复制路径**三个灵活选项。如果你正在使用的自研智能体不在自动识别列表里，只需点击「安装到其他目录…」并指向该智能体读取 `SKILL.md` 的技能文件夹，或者把 zip 包存下来交给你的助手自行解压安装即可。技能包与 MCP 服务完全可以和平共处：智能体会自动挑选它最顺手的一条通道调用，而两条通道底层执行的文档操作完全等价。

**第二部分：配置 MCP 服务。** 面板提供两条接入路线供你任选：第一条是默认推荐的**由助手按需启动（stdio 模式）**，你只需把界面上生成的标准配置片段一键复制或注入到你的 AI 客户端里，以后每当你在助手里提到办公文档时，助手自己就会在后台静默拉起 `genoffice mcp` 进程干活；第二条路线则是**本地 HTTP 服务**，由 GenOffice 桌面应用自己在后台常驻开启一个本地端口供外部助手随时连入。无论选哪一条路，配置好之后你都不需要再自己去终端里手敲任何命令。

**立刻试一试：** 安装完成后，在你的编程助手里新开一个对话窗口，直接像平时跟同事说话一样交代文档任务即可，例如：

- “帮我把 `~/Downloads/report.md` 转换成排版规范的 Word 文档”
- “根据当前目录下的销售数据，做一份 6 页的幻灯片总结我们第三季度的业绩亮点”
- “把 `budget.xlsx` 导出成 PDF 文件，并直接在 GenOffice 窗口里帮我打开”

## 从终端命令行批量注册（高级路径）

如果你习惯在终端里用脚本管理开发环境，或者你的编程代理安装在一些非标准的自定义目录里，也可以直接在命令行里完成同样的 MCP 注册操作：

```sh
genoffice mcp install all
```

执行这条命令后，`genoffice` 会自动探测当前机器上已安装的所有受支持编程代理，将 `genoffice` 的 stdio MCP 服务器配置项精准合并进每个代理各自的配置文件中，同时严密保护你配置文件里原有的其他 MCP 服务器条目不受影响。

```sh
genoffice mcp list             # where each agent stands
genoffice mcp install cursor    # just one
genoffice mcp uninstall cursor  # take it back out
```

如果你的某个编程代理安装在非默认路径下，可以在命令后加上 `--dir <自定义配置目录>` 参数手动指定位置；如果某个代理里之前已经配过旧版条目、想强制刷新覆盖它，加上 `--force` 参数即可。

在终端运行 `genoffice mcp --help`，就能在一屏之内看清 MCP 服务器支持的全部子命令与启动参数——包括 `install`、`uninstall`、`list` 三种管理动作，切换为 HTTP 模式的网络参数，以及控制 Schema 体积的两个开关：

## 独立启动 HTTP 模式的 MCP 服务器

当你的 AI 客户端运行在容器、虚拟机或局域网内的另一台机器上、无法直接通过本机进程管道（stdio）拉起命令时，可以让 `genoffice mcp` 以带鉴权的 HTTP 服务器模式独立运行：

```sh
genoffice mcp --http 8765 --token <secret>
```

你可以通过 `--host <监听地址>` 指定它绑定的网卡地址（默认仅绑定本机回环地址以保安全），并在你的 AI 客户端配置里填上同一个 `--token` 访问令牌。

走 HTTP 远程模式时，哪怕客户端与 GenOffice 不在同一个文件系统下，文档照样能顺畅流转：客户端可以通过 `PUT /files/<文件名>` 接口先把待处理的文档上传过来，每一个 MCP 工具也都支持直接传入 `http://` 或 `https://` 网址来代替本地磁盘路径；处理完成后，生成的新文档会以可直接下载的 HTTP URL 返回（如果生成的文件体积足够小，也会直接作为内嵌资源返回）。至于结构化的编辑指令（op、spec）和 Markdown 文本，在 stdio 与 HTTP 两种模式下都直接通过 JSON 请求体内联传递。

## 外部智能体通过 MCP 能调用哪些核心工具

`genoffice` 命令行里的每一项核心能力，在 MCP 协议下都会映射为一个结构化的标准工具，其中最常被智能体调用的有：

- **`docs`、`sheet`、`slides` 文档读写与编辑工具**：走与 GenOffice 桌面应用完全相同的底层写入管线，以每次一个或多个 **op（原子操作）** 的粒度精准读取和修改 `.docx`、`.xlsx` 与 `.pptx` 文件；如果是从零创建一整套全新演示文稿，还会配合 `deck_start`、`deck_page` 与 `deck_build` 流水线工具保证版面质量。
- **`render` 页面视觉渲染工具**：由应用内置的真实排版渲染器把文档或幻灯片逐页渲染成高清 `.png` 图片返回给智能体，让支持视觉的智能体能够亲眼“看”到自己排出来的版面有没有文字重叠或溢出，而不是闭着眼睛瞎猜。
- **`pdf` 文字层读取工具**：无需启动沉重的桌面端窗口进程，直接在后台按页高速提取 PDF 文档里的文字内容供智能体阅读分析。
- **`info` 文档结构探针**：快速返回一份陌生文档的页数、章节大纲、工作表名称与元数据摘要，通常是智能体接手一个新文件时用来摸清底细的最佳第一通调用。
- **`search`、`image`、`media` 多模态与检索工具**：直接复用你在 GenOffice 桌面端「设置」里已经配好的联网搜索、AI 生图与音视频理解服务商，这样外部编程代理就不需要自己再去额外配置一套第三方 API 密钥。
- **`merge` 模板批量填充工具**：读取外部键值数据，一键替换并填充办公文档模板里的 `{{key}}` 占位符。

## 精简 Schema 模式：为上下文窗口吃紧的客户端省空间

默认情况下，`apply` 和 `create` 等核心工具在向 MCP 客户端声明自己的 `ops`、`cells` 和 `data` 参数时，会输出由 `genoffice guide <领域> --json` 生成的完整逐操作强类型 Schema。这种完整声明对大模型写出一次成功的合法参数非常有帮助，但 Schema 本身的 JSON 体积也相对较大。如果你使用的某个 MCP 客户端对工具定义的长度有严格限制、或者上下文窗口预算比较吃紧，可以开启**精简 Schema 模式**，将复杂联合类型收敛为轻量的基础数组声明：

```sh
genoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 genoffice mcp
```

## 为什么配了 MCP 还建议安装「技能（Skill）」？

很多用户会好奇：既然 MCP 已经把工具暴露给智能体了，为什么面板里还要提供「技能（Skill）」？原因在于，一个只拿到工具名却没读过操作手册与排版规范的智能体，在面对复杂的公文表格或 PPT 布局时依然容易去瞎猜参数。而 GenOffice 的**技能包（`SKILL.md`）**里直接随身携带了完整的操作指令参考手册与高审美版面设计规范（与你在终端运行 `genoffice guide` 看到的权威指南同源）——装上技能后，智能体在下笔写每一个 op 之前，都是真正熟读过参数规格与排版禁忌的。你既可以在上面介绍的 **设置 ▸ 集成** 面板里点一下按钮安装，也可以在终端里运行 `genoffice skill` 完成安装。

## 与正在运行的 GenOffice 桌面窗口实时联动

GenOffice 的 MCP 服务器绝不仅仅只能在后台闷头改磁盘上的静态文件。只要你的 GenOffice 桌面应用正开着，外部编程智能体就可以直接与你眼前的窗口协同工作：

- **`open_in_genoffice`**：让桌面窗口立刻在一个新标签页里打开指定文件，并自动把该标签页切到最前台呈现给你看。
- **`open_documents`**：实时列出你当前在 GenOffice 窗口里打开的所有文档标签页清单（包含每个标签的唯一 ID、编辑器类型、磁盘路径，以及当前是否有尚未保存的改动），并允许智能体直接读取某个已打开标签页里的最新内存内容、触发就地保存，或者帮你将标签页安全关闭（默认会先保存再关，除非你明确指示丢弃改动）。
- **直接往已打开的标签页里实时写内容**：所有的文档编辑类工具都支持把上面查到的标签页 ID（或文件路径）直接作为 `document` 参数传进去——这样智能体做出的每一处文字润色、表格填数或幻灯片排版，都会**直接实时落在你眼前正开着的那个标签页画布上**，并且主窗口会自动切过去让你亲眼看着修改发生。

当然，有两块纯属桌面交互的领地依然保持独立：MCP 服务不会去操控你窗口右侧的内置 AI 聊天面板，也不会触发应用内的软件版本更新对话框。

## 「本地 HTTP 服务」可视化管控面板

如果你在 **设置 ▸ 集成** 下方选择了**本地 HTTP 服务**模式，GenOffice 桌面端就会亲自替你托管并守护这个 MCP 服务器进程，无需外部助手去操心进程启停。面板上提供了直观的**启用开关**、自定义**端口**输入框、实时显示**运行中 / 未运行**的状态指示灯，以及**后台生成**开关（开启后智能体生成文档时直接静默写到目标磁盘路径，而不会每次都突然弹出一个新标签页打断你），下方还附带了一段可一键复制的**客户端 JSON 配置示例**。当你点开**高级**折叠区后，还会额外展示两条标准连接端点地址（现代的 **Streamable HTTP** 地址与兼容旧客户端的 **SSE** 地址）、一个用于探测服务存活的**健康检查**网址，以及一个**本地活动日志**开关——开启日志后，服务器收到的每一次 MCP 工具调用都会记录到本地日志文件中，你可以随时在面板上一键**打开**、**刷新**或**清除**日志。出于安全隔离原则，该内置 HTTP 服务始终只绑定并监听本机（`localhost`）。
