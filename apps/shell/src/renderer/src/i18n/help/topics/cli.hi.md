# कमांड लाइन और एजेंट

हर इंस्टॉल में `genoffice` कमांड रहती है जो उन्हीं इंजनों को चलाती है जिन्हें विंडो चलाती है — वही पार्सर, वही राइटर, वही रेंडरर। ऐप द्वारा सहेजी गई फ़ाइल और कमांड द्वारा लिखी गई फ़ाइल एक ही फ़ाइल होती है, और जाँच जो ऐप का AI पैनल पास करता है वही जाँच कमांड भी पास करता है।

```sh
genoffice --help          # every command
genoffice guide slides    # the op reference, for writing your own
```

## कमांड पाना

macOS और Windows इसे ऐप बंडल के भीतर भेजते हैं। नाम से उपयोग करने के लिए एक बार `genoffice install-cli` चलाएँ: यह बंडल में मौजूद बाइनरी का सिमलिंक `/usr/local/bin` में, या Windows पर आपके उपयोगकर्ता `PATH` में बना देती है।

## जानने योग्य कमांड

| कमांड | क्या करता है |
| --- | --- |
| `open` | ऐप में दस्तावेज़ खोलता है; ऐप न चल रहा हो तो उसे चालू कर देता है। |
| `convert` | ऐप के अपने इंजनों से प्रारूपों के बीच रूपांतरण करता है। |
| `create` | संरचित सामग्री से दस्तावेज़ बनाता है। |
| `render` | हर पेज के लिए एक PNG, जैसे रेंडरर उसे लेआउट करता है। |
| `pdf` | किसी PDF की टेक्स्ट लेयर को पेज-दर-पेज पढ़ता है, बिना ऐप प्रक्रिया के। |
| `info` | दस्तावेज़ का मेटाडेटा और संरचना सारांश। |
| `search` | ऐप में कॉन्फ़िगरूड प्रोवाइडर से वेब या चित्र खोज। |
| `image` / `media` | चित्र बनाता है, या किसी चित्र, वीडियो या ऑडियो फ़ाइल का वर्णन करता है और उसके बारे में सवाल पूछता है। |
| `merge` | `.docx`, `.pptx` या `.xlsx` टेम्पलेट में `{{key}}` प्लेसहोल्डर भरता है। |
| `capabilities` | बताता है कि इस मशीन पर कौन-कौन से क्लाउड फ़ीचर कॉन्फ़िगरूड हैं। |
| `guide` | ऑप संदर्भ और डिज़ाइन गाइड, उन्हीं परिभाषाओं से बने जिनके विरुद्ध एक्सीक्यूटर सत्यापन करता है — इसलिए यह `apply` जो स्वीकारता है उससे हटकर नहीं जा सकती। `--json` इसे हर ऑप की स्कीमा के साथ देता है। |
| `install-cli` | `genoffice` को `PATH` में रखता है। |
| `skill` | इस मशीन पर मिले कोडिंग एजेंट सूचीबद्ध करता है और उनमें GenOffice स्किल इंस्टॉल या अपडेट करता है। |
| `mcp` | हर कमांड को Model Context Protocol टूल के रूप में परोसता है। देखें **कोडिंग एजेंट जोड़ना**। |

## संपादन: दस्तावेज़, शीट्स, स्लाइड्स

`genoffice docs`, `genoffice sheet` और `genoffice slides` उसी राइट पथ से पढ़ते और संपादित करते हैं जिसका उपयोग ऐप करता है, और वे एक ही शब्दावली साझा करते हैं: एक **ऑप** एक अकेला संपादन है, और एक **स्पेक** क्रम से लागू ऑप्स की सूची है।

```sh
genoffice sheet read report.xlsx
genoffice slides apply deck.pptx --ops ops.json --dry-run
genoffice docs apply brief.docx --ops ops.json
```

`--dry-run` बताता है कि कोई बैच क्या करेगा और कुछ नहीं लिखता, यह वह सस्ता तरीका है जिससे कोई स्पेक लागू होने से पहले जाँच लिया जा सके। ऐप का AI पैनल ठीक इन्हीं ऑप्स पर चलता है, इसलिए जो कुछ आप उससे करवा सकते हैं वह आप स्क्रिप्ट से भी करा सकते हैं।

## Model Context Protocol

`genoffice mcp` हर कमांड को MCP टूल के रूप में परोसता है, और `genoffice mcp install <agent|all>` उसे किसी कोडिंग एजेंट के अपने कॉन्फ़िग में पंजीकृत कर देता है। उस पक्ष के लिए **कोडिंग एजेंट जोड़ना** देखें।

## कमांड क्या नहीं करता

यह फ़ाइल पढ़ता और लिखता है। यह ऐप नहीं है: कोई विंडो नहीं होती, और ऐप के भीतर की अपडेट संवाद लागू नहीं होती। जिसे भी विंडो चाहिए — AI पैनल, रेंडर की गई स्लाइड पर QC जाँच — उसे आपका फ़ाइल खोलने तक इंतज़ार करना पड़ता है। `genoffice render` आपको विंडो के बिना ही पिक्सल दे देता है, और `genoffice slides` डेक के लेआउट की खुद जाँच कर लेता है।
