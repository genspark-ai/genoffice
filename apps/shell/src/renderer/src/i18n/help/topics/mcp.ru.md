# Подключение агента для программирования

GenOffice говорит на языке Model Context Protocol, поэтому агент для программирования может читать, писать и рендерить ваши документы теми же движками, что и приложение. Агент не угадывает формат файла: он получает типизированные схемы op из тех же определений, по которым исполнитель проверяет допустимость.

## Как зарегистрировать

Обычный случай — одна команда:

```sh
genoffice mcp install all
```

Она находит на этой машине агентов для программирования — Claude Code, Codex, Cursor, Gemini CLI, Copilot CLI, OpenCode, Windsurf — и записывает запись stdio-сервера в конфигурацию каждого из них, оставляя остальную часть того файла ровно такой, какой нашла.

```sh
genoffice mcp list             # where each agent stands
genoffice mcp install cursor    # just one
genoffice mcp uninstall cursor  # take it back out
```

Агент, установленный в необычное место, принимает `--dir <path>`; `--force` перезаписывает запись, которая уже там есть.

## Если запускаете сами

Для клиента на другой машине отдайте сервер по HTTP:

```sh
genoffice mcp --http 8765 --token <secret>
```

`--host <addr>` меняет, где он слушает. Передайте клиенту тот же токен.

По HTTP ходят и файлы: `PUT /files/<name>` загружает один файл, каждый инструмент принимает URL `http(s)` вместо пути, а результаты возвращаются как URL для скачивания — а когда они достаточно небольшие, то и как встроенные ресурсы. Op, spec и Markdown в любом случае передаются прямо внутри.

## Что получает агент

Каждая команда — это инструмент. Интересные из них:

- **`docs`, `sheet`, `slides`** — прочитать и отредактировать файл по пути записи самого приложения, по одной **op** за раз. Новая презентация идёт `deck_start`, `deck_page`, `deck_build`.
- **`render`** — по одному PNG на страницу, разложенные рендерером приложения, так что агент может посмотреть на слайд, а не гадать о нём.
- **`pdf`** — текстовый слой PDF постранично, без процесса приложения.
- **`info`** — метаданные и сводка структуры; обычно это самый дешёвый первый вызов для незнакомого файла.
- **`search`, `image`, `media`** — провайдеры, настроенные в приложении, так что агенту не нужны собственные ключи.
- **`merge`** — заполнение шаблона `{{key}}`.

## Схемы и меньший бюджет

`apply` и `create` объявляют свои параметры `ops`, `cells` и `data` вместе с типизированной схемой для каждой op, сгенерированной из `genoffice guide <domain> --json`. Это точно, но не компактно. Клиент с тесным контекстным окном может попросить обычные массивы:

```sh
genoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 genoffice mcp
```

## Skill

Агент, который не знает словаря op, будет гадать. `genoffice skill` ставит skill GenOffice найденным агентам вместе со справкой и руководствами по дизайну — тем же материалом, который печатает `genoffice guide`.

## Чем это не является

Сервер MCP читает и пишет файлы. Это не окно: панели ИИ здесь нет, а диалог обновления внутри приложения не действует. Если какому-то шагу нужно окно — откройте файл.
