## Dependency notes

- Plans 001–003 isolate provider contract, request translation, and streaming
  risk before any authentication or app wiring.
- Plans 004–005 isolate OAuth storage and the Electron IPC boundary. They must
  not read tokens in a renderer or change `AgentLoop`.
- Plan 006 connects the existing Docs `AgentLoop` to the provider and exposes
  only Docs skill tools. It must preserve the existing Genspark path unless the
  operator explicitly chooses to make Codex the only provider.
- Plan 007 was a broad live/package catch-all and is superseded by the concrete
  hardening and final-validation Plans 011–017.
- Plan 009 is a Docs-only UI pass built on the completed provider capability
  path in Plan 008. It changes placement and interaction only; provider
  transport, authentication, and document revision semantics stay untouched.
- Plan 010 replaces Codex's failure-first sign-in recovery with a provider
  selection preflight. It keeps OAuth in the main process, blocks every Docs
  send path until status is confirmed, and leaves Genspark behavior unchanged.
- Plans 011 and 012 are independent root fixes in the shared provider package:
  refresh failures stop destroying recoverable credentials, and Codex reuses
  GenOffice's established fetch/watchdog/activity path.
- Plan 013 is a behavior-preserving extraction required before the Electron
  storage and callback lifecycle tests in Plans 014 and 015.
- Plan 016 depends on Plan 011's confirmed-vs-transient refresh classification
  and reuses the auth boundary extracted in Plan 013.
- Plan 017's original final gate is superseded by Plan 022 because the
  post-implementation audit found shared-boundary work that must land first.
- Plan 018 changes only the Docs main-process credential adapter. Run it before
  the remaining hardening plans; it uses a separate
  `~/.genoffice/codex-auth.json` file for normal operation and requires fresh
  OAuth login instead of importing old safeStorage credentials.
- Plan 019 fixes overlapping-login races at the service and callback
  boundaries. Plan 020 then moves the stable Node adapter out of Docs without
  introducing Electron into the provider package.
- Plan 021 replaces Docs-only message sanitization and hardcoded English with
  safe shared error codes and renderer localization.
- Plan 022's Docs-only packaging gate is superseded because the maintainer
  selected the office-wide rollout before creating the focused Docs PR.
- Plan 023 first externalizes the settled provider/auth/model chrome into
  `@genoffice/ui`, centralizes safe renderer error resolution, and makes the
  existing settings file broadcast persisted changes to every mounted tab.
- Plans 024 and 025 are parallel after 023. Sheets/Slides share a top-level
  settings-owner shape; PDF/Markdown share a panel-owned settings shape. Each
  plan keeps app agents, prompts, tools, and document mutations local.
- Plan 026 follows all renderer wiring. It extracts only Electron-independent
  request orchestration into `@genoffice/ai-provider`, keeps app IPC validation
  local, fixes standalone parity, and becomes the final automated/live gate.

## Accepted architecture decisions

- The maintainer approved the current GenOffice-owned Codex OAuth contract.
- GenOffice owns the auth and Responses transport implementation for this PR;
  it is modeled on established Codex/Pi behavior but does not import Pi, copy
  Pi's code, or read Pi/Codex CLI credential files.
- GenOffice's existing `AgentLoop` and app-owned tool execution remain the
  harness. A Pi migration is a separate future spike, not hardening scope.
- Codex credentials use a separate `~/.genoffice/codex-auth.json` file with
  `0600` permissions; old Electron safeStorage credentials are intentionally
  ignored and users sign in again.
- Docs is the approved reference UX. Sheets, Slides, PDF, and Markdown reuse
  that provider/auth/model behavior without changing their app-owned agents.
- Provider, Codex model, reasoning effort, and service tier are suite-global.
  Persisted changes broadcast immediately to already-open sidebars and apply
  to the next send; in-flight runs keep their starting settings snapshot.
- Shared renderer chrome belongs in `@genoffice/ui`. Shared auth/settings/stream
  orchestration may live in `@genoffice/ai-provider` only when it remains pure
  TypeScript with no Electron import. Channel registration, sender validation,
  localization adapters, and app-specific tools remain app-owned.

## Findings considered and rejected

- Replace GenOffice's `AgentLoop` with Codex app-server: rejected for this mod;
  it would introduce Codex's harness and built-in coding tools, contrary to the
  agreed design.
- Make ChatGPT OAuth credentials look like an ordinary OpenAI API key: rejected;
  the ChatGPT subscription backend uses a distinct Codex Responses transport.
- Expand Codex by rewriting app-specific media/search/tool paths: rejected;
  rollout changes provider selection and transport only, while existing tools
  stay owned by their app.
- Read OAuth credentials from the renderer or persist them in `ai-settings.json`:
  rejected for security; credentials belong in the main process credential store.
- Make model selection a renderer-authored free-form string: rejected; Codex
  model availability must come from validated main-process capability data.
- Replace the current implementation with Pi during hardening: rejected for
  this PR because it broadens the dependency and harness surface without fixing
  the concrete refresh, streaming, storage, callback, and status defects.
- Read or share Pi/OpenCode/Codex CLI credential files directly: rejected for
  this migration because those tools own different paths and schemas; GenOffice
  adopts the file-backed JSON pattern in its own `~/.genoffice` namespace.
- Split the mutually dependent provider/auth/Docs wiring into non-runnable PRs:
  rejected. Keep one focused vertical Docs integration PR; split the later
  visual redesign and cross-app rollout instead.
- Restore OS secure storage for Codex credentials: rejected for this PR. The
  maintainer-approved `codex-auth.json` design matches GenOffice's file-backed
  auth convention and already uses stricter atomic `0600` writes.
- Build a generic cross-app Electron IPC framework: rejected. Plan 026 shares
  only pure request orchestration; each app retains its channel registration,
  sender validation, storage path, localization, and app-only handlers.
- Copy the Docs Codex controller and controls into four panels: rejected because
  five async/auth/capability implementations would drift. Extract the settled
  chrome once and integrate it through structural adapters.
- Store provider/model settings per app: rejected by the maintainer in favor of
  one suite-wide configuration with live updates across mounted tabs.
- Cancel or restart active runs when global settings change: rejected. Changes
  affect the next request; mutating an in-flight provider call is surprising
  and unnecessary.
