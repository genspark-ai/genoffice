Follow-up with the deeper root cause and the fix: **#2154**.

Digging past the two defects above, the amplifier turned out to be the measure pass itself: `.measuring-natural` hides gap widgets with `display: none`, and a display:none'd gap **table row** leaves the table grid — so a rowspan crossing it extends over more rendered rows (the hidden slot no longer counts), every later row's cells shift one column, and in a fixed-layout table the shifted cell collapses to zero width. Its text then wraps one character per line (~20 lines for a 40-character list item, ~975 px), the row measures page-tall, `planRowSplit` splits it across pages, and the row-fill patch bakes the height into the DOM. Measured live on the group-head row: cells at widths 170/700/**0**.

The fix keeps the gap row in the grid at its real height during measure (`gapAbove` already subtracts it from the rows below; the block height is now tiled gapless so the last row doesn't absorb the gaps), plus the two items from the previous comment: rows inside a vertical merge take the zero-height cut marker instead of an in-cell band, and `_placeTable` charges vMerge continuation rows to the column like any other row. The e2e spec reproduces the exact shape; both the css and the guard mutations turn it red.
